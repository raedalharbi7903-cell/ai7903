### Historical object discovery and review

git fsck --full --no-reflogs exited 0, reported no corruption, and revealed seven
dangling commit roots plus 102 dangling blob roots. An expanded unreachable scan
found 140 objects in total. The difference is referenced subobjects, not lost data.
Reviewed commit metadata: old Engineering/Architecture documentation, earlier
crypto pipeline/backtest/calibration checkpoints and amended repository-quality
documentation. All current live implementation remains on the feature branch.
Rather than assume archived versions disposable, all objects were packed.
All 110 blob contents were scanned for recognized private-key/provider-token/
credential-URL patterns (no findings); total source blob bytes 148,529.
This is a limited heuristic review, not a guarantee against every possible secret.

### Safe recovery procedure

Do not automatically unpack into the active working tree, merge, execute old code,
change branch or replace verified source.

1. Verify the archive without changing source:
   `git verify-pack -s docs/handover/evidence/recovery-objects-5adf3bd68ef8bb13ff6650231da70dae89fc1165.idx`.
2. Inspect object IDs and history metadata in recovery-object-inventory.json.
   Existing local objects may be read using `git show <commit>`.
3. If recovering after a fresh clone, perform forensic extraction in a separate
   disposable Git repository. Git Bash can feed the pack to
   `git unpack-objects < /absolute/path/to/the.pack` in that disposable repository.
   Some commit parent histories belong to the main preserved repository; fetch/import
   the preserved feature history there before complete historical traversal.
4. Review any recovered content and sensitive data before use. Restore only
   specifically approved material through normal reviewed commits; no merge implied.

The recovery archive is data in docs/, not an automatically loaded Git object store
and not production source. No dangling object was deleted or garbage-collected.
